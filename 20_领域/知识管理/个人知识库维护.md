# 个人知识库维护

> [!abstract] 长期责任
> 持续维护原个人知识库 `data_Lgx` 的可用性、组织语义、来源与维护机制。本库提供方法、规则和工具底座，原库仍是个人内容与实际整理成果的主要位置。这项责任不因某轮整理项目结束而终止。

上级入口：[[20_领域/知识管理/知识管理]]。

## 对象与分工

| 对象 | 职责与边界 |
|---|---|
| 原库 `data_Lgx` | 本机位置为 `D:\O\file\data_Lgx`；保留个人内容、实际使用流程、原始资料和经确认的整理成果 |
| 当前库 | 维护项目、方法、规则理解、工具能力与必要摘要，不默认复制原库个人或工作原文 |
| 用户 | 决定结构意义、优先级、允许的变更范围及验收结果 |
| Copilot | 在约定范围内核验、提出方案、执行获准操作并验证，不能把推断当作已批准规则 |

## 长期维护标准

- 重要内容应可从合适入口找到，来源与必要上下文可追溯；不把“放进某目录”当作全部整理目标。
- 保留有意义的时间线、行动现场、知识挂靠和前缀语义；是否采用或改变某种机制，以原库实际使用和用户确认结果为准。
- 区分现行规则、探索方案、历史记录和未核验事项，避免让 Agent 同时执行不同阶段的设想。
- 维护记录要说明范围、日期、证据和验证结果；不把抽样检查说成全库完成。
- 长期有效规则只接收经过核验与用户确认的结论，不直接将项目诊断假设转成规范。

这些标准用于当前维护工作的治理，不宣称已经替代原库现行约束。

## 操作与数据边界

- 实施前重新读取原库当时生效的约束，核对准确路径、工作区状态、出链与反向链接。
- 对批量移动、合并、删除、规则重写或 Obsidian 配置变更，先确认具体范围、影响、保留内容与恢复方式。
- 不擅自移动或合并整个 vault，不以整理为由删除原始材料或替换原库配置；不覆盖用户已有未提交改动。
- 隐私目录、敏感内容和附件正文默认不纳入探索与整理范围，确需处理时先确认路径、用途与边界；不向外部服务上传原库内容。
- 本库仅保存必要摘要和来源位置，不复制个人原文、凭据或完整会话。原库变更按其生效约束记录。
- 原库本机链接不是当前 vault 内链，其他设备上需重新核验；本库的 CODE + PARA 不自动成为原库的组织规则。

## 例行维护

| 触发情况 | 维护动作 | 何时另立项目 |
|---|---|---|
| 新输入积累、内容难以找回 | 核对入口、处理状态与归属，按已确认机制整理 | 需要批量重分类、历史内容清理或跨目录调整时 |
| 规则、目录用途或工作方式变化 | 对照实际使用，更新受影响说明、导航与必要模板 | 涉及规则体系重写或多种机制协调时 |
| 时间或任务阶段结束 | 按原库生效机制回顾记录、索引和归档，保留上下文 | 联动方式失效或需重建历史链路时 |
| 阶段项目验收 | 接收有效维护方式，登记遗留事项和后续责任 | 遗留事项形成新的明确成果和结束条件时 |

固定回顾频率尚未由用户确认，先按触发条件推进；不虚构已经开展的定期维护。

## 项目成果如何回到领域

接收项目成果时，记录用户确认的有效机制、适用范围、核验日期、例行维护方式和遗留事项去向。只在原库真正实施并验收后，将其登记为已落地机制。

截至 2026-10-25，本轮尚未修改原库，也没有已验收的试点机制；已有理解与候选问题保留在 [[10_项目/个人知识库首轮整理/现状诊断]]，不提前固化。
