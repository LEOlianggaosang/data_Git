# 建库过程与方法

所属项目：[[10_项目/Agent知识库建库/项目总览]]。

## 复现脉络

对现有智能体库不满时，可在确认保留范围、备份并取得清理授权后推倒重来，再沿以下脉络从零搭建；复现职责、结构与运行机制，不复刻历史内容或界面状态。

1. **仓库与边界**：建立或沿用 Git 仓库，约定仓库根为唯一 vault，按 [[README]] 明确两库分工与管理边界。
2. **根入口**：创建 [[README]]、[[PLAN]]、[[INDEX]]、[[AGENT]]、[[DIFF]]，按下文五类职责分工。
3. **CODE、PARA**：按 [[PLAN]] 建立六个分区与首个建库项目，记录目标、方法与验收，并补齐 [[INDEX#文件夹树|文件夹树]] 和 [[PLAN#工作流|工作流图]]。
4. **分布式约束**：核心规则放入 [[AGENT]]，具体细则留在所属文档，并创建 [Copilot 项目入口](../../.github/copilot-instructions.md)引用核心规则。
5. **模板、日记共用**：以仓库根打开 Obsidian，按 [[90_系统/系统说明#Obsidian]] 启用并配置 Templates、Daily Notes 与共用模板，[[DIFF]] 只作每日摘要入口。
6. **验收、复盘**：按 [[10_项目/Agent知识库建库/项目总览#验收]] 走通一次“收集 → 归位 → 提炼 → 输出 → 记录”，核验链接与配置，并消除重复。

## 可复用方法

提炼抽象概念以帮助理解，按概念维护，不按会话轮次累加。

1. **说明、规划、导航、约束、更改**：分别承担本库说明、整体结构把控、内容定位、行为规范与变更追溯。
2. **CODE、PARA**：分别负责信息处理与内容组织。
3. **分布式约束、日记共用**：规则随职责分布，Daily Notes 与 Agent 变更记录共用一份日记。
4. **规则库、灵感库**：Agent 沉淀可复用知识与规则，用户保留个人输入与判断，两库协作而不替代。
5. **树视图、流程图**：分别呈现目录的文件夹结构与知识库的工作流。
6. **正文、元数据、会话记录**：分别承载内容本体、属性描述与尚未被主体笔记承接的接续信息。
