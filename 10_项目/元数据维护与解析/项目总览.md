# 元数据维护与解析

## 目标与范围

形成可验证的元数据维护与解析方案；当前方案仍为草案，不批量补属性、迁移模板或启用解析器。

合并阶段保留既有属性，不批量裁剪或统一；合并后优先参考主工作树的处理方式，再由本项目比较、试验和优化。

后续归属见 [[10_项目/项目区说明#智能体库|项目区说明]]；未验证方案仍留在本项目。

## 主工作树的应用

| 场景 | 已用字段 | 本库研究重点 |
|---|---|---|
| 通用笔记 | `type`、`created`、`tags` | 类型、创建日期与标签的最小表达 |
| 项目 | `status` | 表达生命周期，不复制任务看板 |
| 日记录 | `date`、`created`、`timezone` | 主工作树使用 `type: daily`，本库使用 `type: log`，不能直接套用整份模板 |
| 会话 | `updated` | 样例使用带时区的分钟时间；日志说明则仅用日期，需区分字段语义 |
| 能力条目 | `category`、`scope`、`last_verified` | 领域专用属性，不扩展为所有笔记的必填项 |

本库增量：会话身份卡按 [session-records 的最小约定](../../.github/skills/session-records/SKILL.md#身份卡)使用 `session_id`（本库 UUID）与 `source`（宿主来源），不扩展为全库必填属性；其余字段、解析及批量维护仍待验证。

## 维护方案

- 候选最小字段：知识笔记用 `type`、`created`，日记录用 `type`、`date`；有生命周期才用 `status`，有检索用途才加 `tags`。
- `created` 表示创建，`updated` 只随实际内容变化更新，`last_verified` 只随真实核验更新；不因读取、触发或措辞无变化而刷新。
- 新建时按笔记用途选模板，已有属性按需维护；保留未知字段，不为统一外观批量重写。
- 根规则等无 frontmatter 的文件允许作为例外；模板中的日期占位符不是已经发生的日期。

## 解析边界

- 用 YAML 解析器处理 frontmatter，不用正则替代完整解析；尚未选定解析库及 YAML 版本。
- 区分缺失 frontmatter、空值与语法错误；重复键、非法头部类型等错误须报告文件、位置与原因，不以空对象兜底。
- 按文件用途验证日期、时间与标签类型，覆盖带引号日期、日期值及模板占位符，明确时区和内部表示。
- 写回前后保留正文、未知属性与必要注释；内容未变则不写入。

## 下一步与验收

- [ ] 确认最小字段、字段类型与无 frontmatter 的适用范围，不提前形成全库强制标准。
- [ ] 对主工作树模板、会话样例和本库日记录做只读解析试验，覆盖列表、重复键、非法日期及模板占位符。
- [ ] 验证差量写回：无变化零写入，正文和未知字段不丢失，再决定是否落地工具。
