# 知识管理

持续维护知识的采集、归类、提炼、链接和回顾方式，区分智能体库的日常维护与对个人知识库的长期辅助。领域承接长期责任；有明确结果、可验收并结束的一轮改进另建项目。两库的编辑主体与关系以 [[PLAN#两库称呼与分工]] 为准。

## 管理范围

| 对象 | 长期职责 | 入口 |
|---|---|---|
| 智能体库（当前 Obsidian vault） | 本库的内容组织、来源、模板、Agent 工作日志、导航与变更记录 | 本页及 [[PLAN]]、[[AGENT]] |
| 个人知识库 `data_Lgx` | 辅佐维护可用性、组织语义与整理机制，不接管用户的日常内容输入 | [[20_领域/知识管理/个人知识库维护]] |

## 阶段改进

- [[10_项目/个人知识库首轮整理/项目总览|个人知识库首轮诊断与试点整理]] — 有限诊断与一条经确认的试点，完成后将维护方式和遗留事项移交领域。
- 不将所有长期改进都挂在一个永不结束的项目中；新一轮工作须有明确成果、范围和完成条件。

## 本库例行流程

- 将新输入先放入收集箱，再判断 PARA 归属。
- 为重要主题维护 Markdown 索引，关联原始来源与相关笔记。
- 通过 Daily Notes 或 Agent 使用 [[90_系统/模板/每日笔记模板]]，在同一每日文件中记录工作与变更，不维护本库个人日记；接续方式见 [[90_系统/Agent工作日志说明]]。
- 有长期价值的结论提炼到项目、领域或资源笔记，任务状态仍在对应项目维护。

以上是智能体库的工作方式，不自动套用于个人知识库。个人知识库的操作与数据边界见 [[20_领域/知识管理/个人知识库维护]]。
