# 建库过程与方法

所属项目：[[10_项目/Agent知识库建库/项目总览]]。

## 复现脉络

依据 [[90_系统/变更记录/2026-10-26|本次更改记录]]，合并同类调整，按搭建依赖整理为以下复现步骤；时间链接定位历史依据，不要求重演每轮修改或界面状态。若因不满旧库而重建，先确认保留范围、备份并取得清理授权。

1. **建立最小骨架**：建立或沿用 Git 仓库，以仓库根为唯一 vault；创建 [[README]]、[[PLAN]]、[[INDEX]]、[[AGENT]]、[[DIFF]]，按 [[PLAN]] 建立六个分区与首个建库项目，记录目标与验收（[[90_系统/变更记录/2026-10-26#09:34 · 重建 Agent 知识库|09:34]]）。
2. **明确概念与职责**：在 [[README]] 声明术语、两库分工与正文边界，分清五个根入口的职责；在 [[PLAN]] 明确 CODE、PARA 与知识流动性（[[90_系统/变更记录/2026-10-26#10:19 · 强化说明与规划职责|10:19]]、[[90_系统/变更记录/2026-10-26#10:40 · 明确两库概念与正文边界|10:40]]、[[90_系统/变更记录/2026-10-26#14:46 · 明确正文与知识流动性|14:46]]）。
3. **接通约束与共用日记**：[[AGENT]] 只保留核心规则与精简复盘要求，由 [Copilot 项目入口](../../.github/copilot-instructions.md)引用；按 [[90_系统/系统说明#Obsidian]] 配置 Templates、Daily Notes 与共用模板，[[DIFF]] 只作日期摘要入口。本次沿用并核对旧配置，从零复现时需显式配置（[[90_系统/变更记录/2026-10-26#09:34 · 重建 Agent 知识库|09:34]]、[[90_系统/变更记录/2026-10-26#09:51 · 追加精简复盘规则|09:51]]）。
4. **补齐结构与工作流视图**：在 [[INDEX#文件夹树]] 呈现实际文件夹，在 [[PLAN#工作流]] 展示处理闭环，核对树与目录、图源与展示块一致（[[90_系统/变更记录/2026-10-26#10:54 · 增加目录树与工作流图|10:54]]）。
5. **按需展开主题与研究**：将元数据、会话研究拆为独立项目，不阻塞建库验收；有实际材料的智能体管理主题归领域，不预建其他分类（[[90_系统/变更记录/2026-10-26#11:47 · 拆分研究项目与建立智能体管理|11:47]]）。
6. **逐项整合旧资料（有资料且获授权时）**：分别确认正文、规则、原件及证据的去留，按当前结构归位；旧日志独立归档，不因恢复资料而覆盖模板或启用旧自动机制（[[90_系统/变更记录/2026-10-26#16:56 · 按项确认增量整合|16:56]]）。
7. **核验与精简复盘**：检查本地链接与锚点、导航可达性、目录和配置匹配；整合资料核对原件哈希，消除重复，按批次记录结果。提交、合并与推送另取授权，不作为建库必做步骤（[[90_系统/变更记录/2026-10-26#18:05 · 整合提交前核验|18:05]]）。

现有库的骨架与整合检查已完成；仍需在[[10_项目/Agent知识库建库/项目总览#验收|无旧配置空目录]]走通一次完整 CODE 与共用日记录，不能以本节整理代替验收。

## 概念抽象

保留帮助自己理解本库的概念及其关系，不要求普遍适用；按概念维护，不按会话轮次累加。

1. **概念声明**：先明确术语的含义、职责与边界，再据此组织内容与分工；定义与示例见 [[README#概念]]。
2. **说明、规划、导航、约束、更改**：分别承担本库说明、整体结构把控、内容定位、行为规范与变更追溯。
3. **CODE、PARA**：分别负责信息处理与内容组织。
4. **知识流动**：目录是当前归属而非知识边界，正文随用途与阶段迁移、提炼或引用复用；原则见 [[PLAN#建立与演进]]。
5. **分布式约束、日记共用**：规则随职责分布，Daily Notes 与 Agent 变更记录共用一份日记。
6. **规则库、灵感库**：Agent 沉淀可复用知识与规则，用户保留个人输入与判断，两库协作而不替代。
7. **树视图、流程图**：分别呈现目录的文件夹结构与知识库的工作流。
8. **正文、元数据、会话记录**：分别承载内容本体、属性描述与会话身份及按需内容；边界见 [[90_系统/系统说明#会话记录]]。

## 经验沉淀

从本次建库的取舍中总结，不与概念定义混写，也不自动升级为全库规则。

1. **重建不等于全盘恢复**：旧资料、规则与自动机制分别评估；保留原件和证据，不代表沿用旧结构或制度。
2. **先可用，再研究**：骨架先验收，变动中的探索独立推进，稳定成果再回流，避免建库成为永不结束的研究。
3. **精简看联动成本**：不只缩短单篇，更要减少一次变化牵动的文档与触发链，避免记录再催生记录；参见 [[40_归档/旧更改记录/2026-10-26#03:43 · 收缩记录触发与分层导航|联动收缩记录]]。
4. **验收不越过证据**：链接、目录、配置和哈希检查不能代替真实使用；空目录复现、会话运行等未执行项保持待验证，不提前宣布可用。
