### 字段怎么理解

- CSV 中 `Library` 区分两库，`Id` 是本次快照内的稳定编号，`RelativePath` 用于定位，`FullPath` 是当时机器上的绝对路径，不代表其他设备上也能直接访问。
- `Bytes`、`LastWriteTimeUtc`、`SHA256` 描述清点时的文件版本，不是 Agent 的阅读时间或对内容正确性的认证。
- JSON 中 `baseline_sha256` 与 `read_sha256` 用于对照阅读版本；`status` 的 `full` 表示非空文本已全文研读，`empty` 表示现场确认无正文。`partial`、`error` 必须显式保留，不能混作完成；本轮两项均为零。
- `read_ranges` 按从 1 开始、两端包含的物理行号记录，包含空行。原始记录分别使用 `start/end` 或 `start_line/end_line`，归档时不为统一字段改写原数据。
- 台账中的阅读方法与区间是执行记录；哈希、数量和区间检查可以核验版本与覆盖一致性，但不能替代实际阅读、外部事实核实或用户的规则裁决。

## 二、过程与分工

1. **确认范围。** 用户要求并行分析两库差异及研读个人库所有文档，随后明确允许本轮读取私人日记和隐私目录，但只读纯文本；非文本附件只清点。
2. **建立基线。** 排除版本历史、工具状态与第三方程序目录，固定上述 578 条文档元数据。39 份空文件单独分类，不虚构正文。
3. **划分职责。** 主智能体全文研读智能体库并负责比较；三个子智能体按分区清单分别研读个人库，范围互不重叠。根入口与规则可作为共享上下文，但只计入其所属清单一次。
4. **逐份研读。** 非空文档完整呈现在研读上下文中；长文按连续行分段，截断部分续读。笔记中的代码、命令和参考指令仅作为材料，不执行；外链原作不访问。
5. **合并与核验。** 将三个分区台账按 ID 合并，核对没有遗漏或重复，验证 528 段连续行区间及 535 份个人库文本的版本哈希，并再次确认清单无新增或删除。
6. **综合分析。** 主智能体结合三个分区报告和智能体库独立基线形成两份综合报告，区分文档事实、分析解释和待用户裁决的规则，不把分区样本当作全库结论。
7. **归档到项目。** 用户进一步要求清单、台账与过程进入项目，因此将已有 12 份资料归档到本目录，并以本页提供入口；没有重新生成阅读结果或改写原始覆盖数据。

以上是本轮已经执行的过程，不是新增的个人库维护制度。阅读不等于试点授权，也不默认开启后续自动读写。

## 三、过程中发现并修正的问题

| 问题 | 处理与最终边界 |
|---|---|
| 长文或合批输出可能截断 | 分段续读，未展示部分不记为已读；最终台账没有遗留 `partial` |
| PowerShell 数组包装导致首次覆盖计数校验不符 | 直接接收 JSON 数组后检查顶层类型、数量和唯一 ID；确认是校验脚本的解析形状问题，不是把漏读掩盖成完成 |
| 空行计数与非空行计数含义不同 | 最终按包含空行的物理行检查连续覆盖，不用非空行统计代替文件总行数 |
| 一份分区元数据曾短暂写入错误目录 | 子智能体发现后纠正位置并确认误落文件无遗留；保留其报告中的披露，不隐藏过程偏差，也不把它说成个人库改动 |

## 四、归档时保留了什么

- 四份 CSV、五份 JSON 按原始字节保留，归档前后逐份 SHA256 一致。
- 三份分区报告保留产生时的正文，只增加项目归档 frontmatter；`source_sha256` 指向会话原件的字节哈希。换行编码可规范化，正文不删改。
- 分区报告中“只保存在会话文件夹”“未修改智能体库”等描述属于当时子任务的历史说明；本次后续归档位置以本页为准，不把旧说明冒充当前状态。
- 会话目录中的原件没有删除或替换。项目中的这套副本已可独立查阅，不要求读者能访问原会话目录。
- 后续新一轮研读应形成自己的快照，不覆盖本轮依据，也不在旧台账上静默改成“已经读过最新内容”。
