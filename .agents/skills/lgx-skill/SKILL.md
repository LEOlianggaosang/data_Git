# lgx-skill

**最高设计优先级：与库内容解耦。** 不覆盖宿主约束；不依赖原库正文、规则、导航、日志、模板或会话数据。必要资源随技能携带，使用内部相对链接；路径、数据与工具作为显式输入。

归属为**个人**，作用范围默认**单库级**，职责按**概念模块**划分；三者与安装位置分开声明。个人技能可存工作区，不因此绑定库内容；不替用户扫描外部库或个人目录。

## 调用接口

操作名是意图接口，不是独立命令或 API。用户 `/lgx-skill <要求>` 默认 `design`；外部调用未指定操作时默认 `audit`，不得升级写入或自动调度其他技能。

| 操作 | 输入 | 输出／权限 |
|---|---|---|
| `design` | 概念、要求、目标位置或既有技能 | 方案或获批文件；仅用户显式 `/lgx-skill` |
| `audit` | 草案／技能标识、获准检索范围 | 交集证据、唯一归属与接口方案；只读 |
| `list` | 可选模块过滤 | 内部模块参考中的声明及实际可用状态；只读 |

无参数设计先询问概念；缺少审核对象、范围或操作不明时澄清，不生成空技能。外部请求 `design` 时拒绝并提示显式调用；`audit/list` 全程零写入。无法读取或加载时报告覆盖不足／未核验，不冒充已查重或已可用。

## 设计与查重

1. 明确单一概念、归属、作用域、输入输出、边界、触发方式及只设计／创建／修改；写前确认位置，仅询问影响设计的缺项，使用宿主提问工具或等待回复。
2. 设计必先走 `audit` 逻辑：在获准范围先看同属个人技能的名称与描述，再读相关正文，对比语义和接口；不凭位置认领插件或库专用技能，不把同名当作可覆盖。
3. 交集先复用，必要时吸收最小共性到合适的唯一所属模块，其他模块仅留接口；契约明确输入、输出、边界、依赖状态。跨技能改写、合并或新建共享模块须确认，不复制正文、不预建系列、不递归自调。
4. 名称为 `lgx-<英文概念>`，满足 `^lgx-[a-z0-9]+(-[a-z0-9]+)*$` 且不超过 64 字符，目录与 `name` 一致；歧义先确认。默认单个 `SKILL.md`，确需才拆资源；frontmatter 含 `name`、有意义的 `description`、`user-invocable: true`，默认 `disable-model-invocation: true`，开放外部接口须明确授权。
5. 仅在获批范围落盘、保留既有改动；只设计、审核、查询均不写。设计不等于执行新技能，不自动改全局规则、安装或启动依赖；缺失接口报告阻塞，不代建。

## 验收

核对 YAML、命名、链接、唯一职责、交集归属和迁移解耦；删除重复、空章节与无用抽象。覆盖正常、缺输入、越权、依赖不可用，脚本做最小测试。反馈归属／作用域／模块、产物、接口、查重覆盖和未完成项；区分文件已定义、宿主已发现、调用已验证，不虚报成功。
