# 会话记录探究与计划

## 目标与范围

形成低维护成本的会话接续与触发方案，独立于建库推进；显式触发及日志解耦已确认采用，现行规则见 [[90_系统/系统说明#会话记录]]、[[90_系统/系统说明#变更记录]]。运行验证与自动化仍待研究，不预建会话文件、提示词或 Hook。

后续归属：稳定成果移交“知识库维护”领域，未验证方案仍留在本项目。

## 问题与分工

会话摘要若随轮末反复更新，再牵动日记录和更改入口，会放大维护成本；不能把“发生了一轮对话或文件变化”直接当作保存会话的理由。

- **会话记录**：保存尚未被正式笔记承接的背景、边界、待决问题与接续点。
- **更改记录**：追踪正文、规则、路径或配置的实质变化，不复制聊天过程。

## 触发方案

按系统说明执行显式保存与纯摘要更新的例外，本项目不另维护第二套触发规则。

## 记录格式

沿用原会话的属性结构；`created` 取首次建档日期，`updated` 记录实际变更的分钟与时区。解析与属性维护另由[[10_项目/元数据维护与解析/项目总览|元数据项目]]验证。

```markdown
---
type: session
status: active
created: YYYY-MM-DD
updated: "YYYY-MM-DDTHH:mm+08:00"
tags:
  - agent
  - session
---

# 主题

## 范围

## 接续点

## 关联
```

## 实现路线

1. 在首次真实保存需求中验证最小记录与写入次数，不以本次格式说明代替运行验证。
2. 根据接续质量调整格式，正文与任务状态仍留在主体笔记；只维护最近一级入口，不逐轮改写根导航。
3. 显式流程稳定后再考虑封装提示词；自动 Hook 需先核验宿主、权限、输入上下文和失败反馈，不把钩子触发等同于摘要生成能力。

## 自动事件探究

| Copilot 事件 | 官方语义 | 候选用途与限制 |
|---|---|---|
| `preCompact` | 上下文压缩前 | 评估接续信息保存，先核验上下文可见性与写入时机 |
| `agentStop` | Agent 结束当前轮 | 不默认保存，避免退化为每轮维护 |
| `sessionEnd` | 会话终止 | 核验收尾能力，不能假设终止后仍能生成摘要 |

以上是官方共享 Copilot 运行时的命名；旧 Local 或其他 Harness 的事件、载荷与配置不可直接套用。当前会话尚未实测这些事件。
