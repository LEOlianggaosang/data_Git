# 思路变迁

只记录影响设计的取舍与依据，不逐轮保存讨论；最新设计见 [[10_Projects/会话记录探究与计划/当前方案]]。

## 演变

| 时间 | 当时思路 | 变化原因 |
|---|---|---|
| 2026-10-26 | 明确要求时保存最小接续摘要，与变更日志解耦。 | 避免每轮更新摘要，再连带维护日记录和入口。 |
| 2026-10-27 10:23 | 按接续、原始会话、自动化三个方向管理研究。 | 分开验证接续效果、宿主记录能力与事件触发。 |
| 2026-10-27 10:43 | 变更条目标会话来源，后建摘要再关联。 | 内容不重复，但应能追溯由哪个会话完成；当时未要求先建本地卡。 |
| 2026-10-27 10:57 | 身份卡先行，内容按需填充；首次引用或明确保存时建档。 | 日志有本库链接，回复切片也不必被整理成摘要。 |
| 2026-10-27 11:26 | 一个仓库级 Skill，分建卡、切片、接续摘要与读取接续。 | 复用显式流程；加载不等于保存授权，Skill 不等于 Hook。 |
| 2026-10-27 12:59 | 先落实更改来源与本地身份卡联动，五项触发能力只预留接口。 | 提前稳定引用，减少未来回溯修改；后续按快照、恢复、内容、原始记录、迁移数据递进。 |

依据：[[90_System/变更记录/2026-10-26#16:56 · 按项确认增量整合|10-26 规则确认]]、[[90_System/变更记录/2026-10-27|10-27 方案推进]]。

## 显式摘要基线

原格式包含 `type: session`、`status: active`、`created`、`updated`、`tags: [agent, session]`，正文为“范围／接续点／关联”。`created` 取首次建档日，`updated` 记录实际变更的分钟与时区；身份卡字段当时尚未确定。

下表为原显式摘要方案的预期值，**均未执行，不作为身份卡方案的验收结果**；日记录按任务批次计条目。

| 情景 | 会话笔记写入 | 日记录 |
|---|---|---|
| 普通答疑，无保存触发 | 0 | 0 |
| 仅项目正文实质变化 | 0 | 1 条 |
| 显式保存有新增接续信息，无正文变化 | 更新原篇或首次建档 1 次 | 0 |
| 重复触发且内容未变 | 0，含 `updated` | 0 |
| 正文变化与会话保存同时发生 | 1 次 | 1 条，不复制摘要 |

## 自动事件备忘

`preCompact`（压缩前）、`agentStop`（单轮结束）、`sessionEnd`（会话终止）仅作候选，均未实测；其他 Harness 不可直接套用，也不能从事件触发推断能读取上下文或生成并写入摘要。
