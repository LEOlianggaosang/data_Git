## 盘点范围

| 范围 | 盘点对象 | 说明 |
|---|---|---|
| 工作区/仓库 | 项目指令、文件指令、智能体、Skills、Hooks、MCP 配置 | 例如 `.github/`、`.vscode/mcp.json`、`AGENTS.md` |
| 用户配置/配置档案 | 个人指令、智能体、Skills、MCP 与工具授权 | 需逐个核对 VS Code 配置档案；不得把当前用户配置当成仓库配置 |
| 扩展/插件 | Copilot 扩展、扩展贡献的 Agent 能力和工具 | 已安装不等于 Copilot 能调用；要通过当前工具注册表验证 |
| 会话运行时 | 本轮 Skills、可委托 Agent、MCP Server 和工具注册表 | 动态快照；由当前会话与工具发现结果核验 |
| 组织/远程服务 | 组织策略、托管 MCP、远程 Agent/工具等 | 不可访问时标为“未核验”，不能推断不存在 |
| 外部参考 | 官方手册、协议、第三方能力介绍 | 仅作为资料来源，不代表当前已安装或可用 |

## 管理约定

- 每个独立 Harness、插件、技能、工具、MCP Server、智能体、Hook 或指令建立一篇条目，使用 [[90_系统/模板/Agent能力条目模板]]；共享运行时能力可集中登记在分类索引。
- 每条记录至少注明来源/范围、可用性证据和最后核验日期；版本、兼容性、权限与数据边界按能力类型补充。
- 状态使用 `available`（已验证当前可调用）、`configured`（已配置，连接/调用未验证）、`installed`（已安装，但 Copilot 可调用性未验证）、`candidate`、`evaluating`、`unverified` 或 `deprecated`。仅在明确列出的检查范围内使用“未发现”。
- 清点本机用户配置时只记配置位置、服务名和非敏感元信息；不复制令牌、密码、环境变量值或其他凭据。此处维护跨范围目录和使用状态；厂商手册等通用参考资料可放在 `30_资源/` 并由条目链接。
- 当前快照见各分类索引。环境、配置、权限或会话变更后重新清点；不要将单次动态注册表宣称为所有 Copilot 部署上的永久完整清单。
- 新增其他类型的能力时，先评估是否属于现有分类；确有需要再增设索引，避免空建分类。
