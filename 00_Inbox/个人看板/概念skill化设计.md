# 本笔记维护约定：不生成到skill

- **适用范围**：仅管理本笔记的设计输入、生成规范与预览，不能写入后续技能。生成层才是技能规范候选；预览仅为派生展示，不是第二份规则来源，也不证明技能已安装或执行。
- **吸收与清除**：设计需求补充、目录需求补充均为临时输入。每轮将新增内容吸收到对应技能，逐项核验后清除已吸收的内容；保留条目、块标识及跳转链接。未明确、冲突或未吸收内容保留并报告；删去临时内容不撤销已生成规则。
- **同步方向**：任一需求补充发生变化，先更新生成层，再核对并同步根目录章节预览、目录结构预览；生成层变更同样同步两份预览。无相关变化时核对后保持不动，不为同步制造无关修改。
- **预览范围**：根目录章节预览展示五大根文件章节及内容依据；目录结构预览推演所有个人技能可用、部分目录已有示例内容时的实际目标树。规范已确定的路径与示例假定分开标注；示例用具体候选路径，不充当必建规则、不反写进技能规范，不在磁盘创建占位文件。树中直接注明负责技能名，不加链接，不重复根文件；普通正文仅在备注中说明其触发结构生长的依据。
- **会话提醒**：每轮完成后列出吸收到哪些技能、清除了哪些临时内容、两份预览的变化及未完成项。新要求与旧规范冲突先确认，不用旧生成内容抵消用户新意图。
- **实施状态**：本笔记不构成清理、建库、迁移或抓取会话的授权；旧实现差异另行处理，不沿用旧自动接续来限定新设计。

各技能的通用生成规范统一见 [[#通用生成规范|lgx-skill 的通用生成规范]]，各条目只补充本职规则与例外。

## lgx-skill

- 定义：将用户概念或需求转化为可复用的个人技能。
- 库体现：维护 DIFF 中仅含技能名称的概念分组，作为唯一公开登记；内部仅保留必要状态与规则，不再维护第二份完整名称清单。
- 原则：先在获准范围审核同属个人技能的语义交集，明确唯一归属，优先复用接口；模块化、自包含、极简、与库内容解耦。
- 资源：references 统一维护通用技能模板与精简规则，名称查询引用目标库的唯一登记；别名、状态与调用关系另行维护，根文件和目录模板归对应模块。
- 蒸馏：在获准范围检查库中相关正文、规则及现有技能，提取可复用规则；实例与原始材料留在库内，删除或迁移原文另获授权，不把原库路径复制为依赖。
- 输出：职责与交集结论、接口契约、获批规范／文件、验证结果；产物须自包含且可迁移。
- 接口依赖：获准范围内的个人技能定义与相关库内容；显式使用方式由 lgx-grammar 维护，DIFF 文件布局由 lgx-diff 负责。概念分组内容唯一归本技能，变更通过获准写入接口应用，不形成互相递归调度。
- 单指令触发：先询问概念
- 执行调度：用户显式设计：审核交集 → 提方案 → 确认位置与范围 → 创建／修改 → 核验；外部仅 audit／list

### 通用生成规范

- **归属与解耦**：个人、默认单库级、单一概念，命名 `lgx-<英文概念>`；与库内容解耦为最高设计优先级，不覆盖宿主约束。各概念唯一维护规则，库内只留实例选择、必要例外与入口。
- **最小产物**：默认仅 SKILL.md，包含名称、有效触发描述、定义、库体现、原则、边界与流程；资源、目录及报告按需创建。每个技能明确实际维护对象或获准的简述位置；可复用规则与库实例分离，未明确位置时报告待定。通用模板与精简规则归本技能 references，专属规范归对应技能；引用不自动启动设计，外部仍仅 audit／list。
- **接口契约**：显式传入操作、根目录、源范围、目标路径／图块、规则、工具和授权；只读查询不要求写目标。返回产物、改动路径、证据、核验与阻塞；调用方核对后才继续。接口声明不等于已实现或宿主已验证。
- **触发与权限**：裸调用默认只读诊断，例外由条目声明；带要求先评估并确认写入范围，具体方案已获批准则不重复询问。职责触发只读评估，外部委托须明确操作与权限；联动、依赖、名称提及均不授权写入或破坏性动作。无权限只交付方案，实际创建时声明开放接口及宿主配置。
- **调度与失败**：概念分组、规则引用不代表执行顺序；实际任务列出 `步骤｜执行技能｜输入／目标｜授权｜前置条件｜完成证据`。缺输入先澄清，读取／工具／依赖失败明确报告，停止受影响动作；无依赖且获准项可继续。不复制缺失实现、不代建技能、不造占位、不扩大到外部库，保留来源、已有及并行改动，不自动回滚他人修改。
- **验收与状态**：分别报告已完成、未执行、失败及核验依据；区分文件定义、宿主发现、接口调用与实际结果验证，生成规范不等于执行授权。未经明确授权不提交或推送。

## lgx-grammar

- 定义：唯一维护个人技能的显式调用语法、参数含义及使用说明。
- 库体现：README 的调用使用简述与实际技能的显式入口说明；不维护第二份技能名称清单。
- 原则：统一使用小写名称；区分“概念”“概念＋内容”“设计”“设计＋概念”四类意图，不把说明中的意图名当作已注册命令。
- 边界：四类语法与具体宿主命令的映射尚待明确；不凭语法授予写权限、改变技能职责或覆盖各技能的特殊入口。
- 接口依赖：lgx-skill 提供已有技能及别名映射，各技能提供真实入口与权限；lgx-grammar 维护语法，不反向调用设计入口，避免递归。
- 单指令触发：查询当前已定义的使用方式，未定义部分明确标待定。
- 执行调度：收集真实入口 → 对照四类意图与歧义 → 确认映射 → 更新获准说明 → 核验说明与实际入口一致。
- 输出：调用语法、示例、权限说明及未注册／未核验项，不虚构宿主能力。

## lgx-clear

- 定义：在适用约束允许范围内限制根目录规则的可选主动读取，减少旧规则对本次任务的干扰。
- 库体现：README 使用简述中说明作用范围、当前提示方式与不能屏蔽的约束，不写入永久豁免规则。
- 原则：明确目标根目录、请求范围和实际可生效范围；不修改规则文件，不声称清空模型上下文。
- 边界：不能跳过仍适用的强制阅读、撤销已加载规则或覆盖宿主约束；无法屏蔽的冲突交回调用方确认，不把未读取当作规则失效。
- 输出：请求范围、可执行限制、仍有效的约束及未解决冲突，不承诺无法实现的屏蔽效果。
- 接口依赖：无独立技能依赖。接收根目录与作用范围，返回可生效的读取限制和仍有效的约束
- 单指令触发：未启用时请求启用本轮会话的可选读取限制；已启用时重复裸调用撤销并恢复正常读取。每次状态变化明确提示，生效期间在相关处理结果中简短提示；无法确认当前状态时先澄清，不猜测切换。
- 执行调度：带内容仅对本条消息生效，不切换会话级状态；重建委托显式给定范围，不默认获得会话级效果；先报告实际生效边界。撤销只解除本技能施加的可选读取限制，不改变任何其他约束。

## lgx-rebuild

- 定义：管理当前目标库的前置检查、获批清理、分步重建与结果汇总。
- 库体现：README 使用简述中说明前置条件、清理确认与重建入口；本次具体执行清单单独输出，不把破坏性动作设为永久默认。
- 清理：对象为获准的根目录文件与主要目录，点文件夹不更改；点文件、隐藏属性项、主要目录、未提交改动的处理须逐项明确。只处理已解析的具体目标，不递归删除仓库根目录，不以通配符、符号链接或目录联接扩大范围。
- 输出：身份、clear 可生效范围、保留／清理清单、逐项重建结果及核验。
- 接口依赖：lgx-clear、lgx-job、lgx-struct、lgx-plan、五大根文件及六分区对应技能。clear 返回作用边界；job／struct 返回骨架规则；plan 返回实例方案；创建接口接收唯一目标和权限，返回逐项状态
- 单指令触发：只读检查身份并展示方案，不删除
- 执行调度：按下述重建阶段执行，先确认精确清理与保留范围

### 重建阶段

1. **身份检查**：lgx-rebuild 核验当前目录是已登记的 Git 附加工作树根目录；不是或无法确认则停止。
2. **读取范围与冲突**：委托 lgx-clear，明确作用范围和可生效限制；仍有适用规则冲突时停止受影响动作，不将屏蔽请求当作绕过依据。
3. **执行计划与清理确认**：列出已解析的目标、点文件夹保留项、点文件／隐藏属性项、主要目录、未提交改动及后续重建接口。取得精确清单和动作授权；关键接口不可用时先报告重建阻塞，不盲目清理。
4. **逐项清理与检查**：只处理获准目标，不递归删除仓库根目录；核对保留项和清理结果。失败不进入依赖清理通过的重建步骤。
5. **规划与骨架**：查询 lgx-job／lgx-struct 的骨架规则，交由 lgx-plan 确定本次实例方案；lgx-rebuild 按本次确认清单调度五大根文件与六分区对应技能。独立图源、元数据说明或日志需要的父目录先由分区接口创建，再交概念技能处理。
6. **依赖核验与展示**：流程语义确定后处理图示；实际结构可用后生成树视图并维护 INDEX；其他根文件只引用已存在的目标。AGENT 与其他根文件的具体先后以获准清单和依赖为准。
7. **结果汇总**：分别核验文件、目录、规划一致性、导航与图表；最后按获准记录规则处理日志、来源与 DIFF 摘要。记录机制若尚未就绪则报告未完成，不冒充完整重建成功。

## lgx-job

- 定义：唯一维护五大根文件的职责、最低结构、别名和相互边界。
- 最低结构：根文件只留实例、必要简述与入口，有实际内容才保留章节，不生成空占位；本技能定义最低结构，各根文件技能承接具体内容。
- 库体现：五大根文件各自的最低章节及 README 功能路标；别名语义与 lgx-statement 对齐，在 INDEX 展示结构别名。
- 原则：根文件各司其职，具体维护交给对应技能，不复制操作流程；模板随本技能携带。
- 模板：AGENT／约束保留极致精简、改前按职责阅读、模块化、结构化；PLAN／规划包含结构理论、本库规划、工作流；INDEX／导航包含目录树视图、结构别名、内容入口；DIFF／差异包含个人技能概念分组、两库差异、更改记录、会话记录；README／说明包含常用概念、应用边界、使用简述、根文件入口。
- 边界与输出：输出职责划分、最低结构与模板差异，不代写五大根文件或调度重建。
- 接口依赖：无独立技能依赖。对外提供根文件职责、别名和最低结构模板，不负责实例文件创建
- 单指令触发：检查职责交集
- 执行调度：评估模板变更 → 确认 → 更新职责规范；只读模板查询不写

## lgx-agent

- 定义：维护根目录 AGENT.md 的核心约束及其一致性。
- 库体现：AGENT 的必要核心规则；按任务涉及的规划、导航、更改、概念与应用分别阅读 PLAN、INDEX、DIFF、README，不免除其他仍适用的阅读要求。
- 原则：极致精简优先；仅保留必要核心声明，细节由所属技能维护。
- 输出：分别报告 AGENT 文件处理与全库诊断状态，不能用文件已创建代替全库一致性结论。
- 接口依赖：lgx-job、lgx-skill、lgx-struct。分别参考根文件职责、模块化与结构化规则，返回必要核心约束，不复制细则
- 单指令触发：诊断核心约束
- 执行调度：读取必要根文件 → 评估 → 确认 AGENT 范围 → 创建／修改 → 核验；其他库优化单独确认

## lgx-plan

- 定义：维护 PLAN.md，确定本库结构与工作流方案，诊断实际结构和规划的一致性。
- 库体现：PLAN 的结构理论、本库规划与工作流章节。
- 原则：规划保留理论、结构与流程的实例选择，不复制上游规则，不让图示反向决定流程。
- 边界与输出：输出 PLAN、规划差异与缺项及核验，不接管清理或全库创建调度。
- 接口依赖：lgx-job、lgx-struct、lgx-design、lgx-workflow、lgx-flow。获取骨架、理论与流程依据；向 flow 传已确认语义、图源／图块范围及权限，接收图示与核验状态
- 单指令触发：返回规划差异与缺项
- 执行调度：读取理论、结构和流程依据 → 确认实例方案 → 修改 PLAN → 按需委托图示 → 核验；不自行接管全库调度

## lgx-design

- 定义：维护知识库采用的方法理论及选用依据，当前基线为 CODE-PARA。
- 库体现：PLAN 的结构理论章节，仅声明本库采用的理论与必要依据。
- 原则：区分 CODE 的信息处理与 PARA 的组织方法，不将某库实例目录、正文或流程复制为通用理论。
- 边界：不直接修改规划、生成图表或迁移内容。
- 输出：理论声明、选用依据、适用条件与差异。
- 接口依赖：无独立技能依赖。提供理论、依据和适用条件，不返回实例目录或擅定流程
- 单指令触发：分别核对理论声明、流程规则
- 执行调度（lgx-design、lgx-workflow共用）：评估规则与影响 → 确认 → 修改明确规范目标；外部只读返回依据，不触发实例修改

## lgx-workflow

- 定义：维护收集、流转、提炼、输出与归档的工作流规则。
- 库体现：PLAN 工作流章节中的语义说明及获准的本地流程例外。
- 原则：明确步骤、条件、循环与终点，区分通用规则与本库选择。
- 边界：不维护图表语法，不代替实例规划，不因描述流程而执行其中操作。
- 输出：明确的工作流说明、规则一致性结论与差异。
- 接口依赖：lgx-design。参考方法理论，提供流程规则供 plan 选择，供 flow 表达
- 单指令触发：分别核对理论声明、流程规则
- 执行调度（lgx-design、lgx-workflow共用）：评估规则与影响 → 确认 → 修改明确规范目标；外部只读返回依据，不触发实例修改

## lgx-flow

- 定义：转换、同步和核验已确定的工作流图示。
- 库体现：PLAN 的工作流图块与明确指定的系统图源。
- 原则：流程语义归调用方；图源与展示图块一致，生成后语法验证并预览，工具缺失明确标未完成，不补造业务分支。
- 边界：只改获准图源／图块，不制定或执行图中流程，不自动安装或上传，不手工覆盖受同步工具管理的图。
- 输出：图源、范围、语义核对、语法验证和预览的分别状态。
- 接口依赖：调用方工作流依据、宿主语法验证与预览工具。render 接收写入授权，check 只读；返回语义、语法、同步与预览的分别状态
- 单指令触发：询问工作流与目标
- 执行调度：render：核对语义与范围 → 生成／更新 → 语法验证与预览；check：零写入核验，不生成新图

## lgx-index

- 定义：维护 INDEX.md，统一提供实际结构与内容的导航。
- 库体现：INDEX 的目录树视图、结构别名及内容入口。
- 原则：内容入口用别名、精确到二级；结构别名与树视图、内容入口分开，不重复根文件职责或元数据策略。
- 边界：核对导航遗漏与失效入口，不判断规划是否落实，不调度创建；规划诊断归 lgx-plan，重建调度归 lgx-rebuild。
- 输出：实际目录树、结构别名与有效内容入口；元数据说明按需作为系统内容入口，不单设重复章节。
- 接口依赖：lgx-tree、lgx-struct、lgx-statement。分别提供树视图、目录职责与结构别名；元数据说明入口取实际维护位置，规划落实不由 index 判断。
- 单指令触发：检查导航准确性
- 执行调度：确认目标 → 委托目录树 → 核对结构别名与实际内容入口 → 更新 INDEX → 核验链接，不补建缺失结构

## lgx-tree

- 定义：根据实际文件系统生成、核验目录树视图。
- 点文件夹：负责在获准根目录只读枚举、记录并更新实际点文件夹列表，生成树视图时复用本次核验结果；仅列一级，不展开内部，不用固定名单代替实际枚举。
- 库体现：INDEX 的目录树图块，不维护相邻入口列表。
- 原则：普通内容精确到文件夹，隐藏文件夹仅列自身、不展开；骨架视图同时列根文件与目录，避免为展示而遍历隐藏配置。
- 边界：不维护根文件或内容入口列表，不判断规划缺项，不创建目录。
- 输出：树文本或获准目标改动及差异证据。
- 接口依赖：无独立技能依赖。接收实际根目录、范围和展示目标，返回树文本与差异，不返回导航入口列表
- 单指令触发：检查已有树视图
- 执行调度：确认根目录、范围和展示目标 → 只读枚举 → 返回树文本或写入获准位置 → 核验

## lgx-yaml

- 定义：维护本库元数据字段、类型与使用约定。
- 库体现：README 常用概念／使用简述中的元数据用途声明，系统目录中的具体维护说明；INDEX 仅按实际内容提供入口。
- 原则：字段规范唯一维护，README 只简述用途，字段按实际需要声明，不虚构必填字段。
- 边界：未知属性保留，字段变更不自动扩展为全库批量回填；字段基线和迁移规则尚待细化。
- 输出：规范目标、字段差异、兼容影响与未定义项。
- 接口依赖：lgx-system（需要创建系统结构时）。获取获准的说明存放位置，字段规范归 yaml；已有位置可复用，不因依赖自动建目录
- 单指令触发：检查指定元数据范围
- 执行调度：评估字段与迁移影响 → 确认 → 必要时委托存放结构 → 更新指定范围 → 核验，禁止自动全库回填

## lgx-diff

- 定义：维护 DIFF.md 的库级差异摘要与相关入口。
- 库体现：DIFF 的个人技能概念分组、两库差异简述、日期摘要及记录入口。
- 原则：技能分组为 lgx-skill 唯一登记的库内展示位置，仅含名称，不另存副本；其他部分只保留必要简述和摘要，不复制详细规则。
- 边界：实质变更纳入记录，纯答疑不计；本技能维护摘要与入口，不接管详细日志或会话正文采集。
- 输出：摘要与入口的实际改动、有效性及记录关联状态，不编造来源或成功状态。
- 接口依赖：lgx-skill、lgx-vault、lgx-change-log、lgx-session-log。引用名称、分工、变更与来源的权威入口，不维护副本；来源关联由日志接口复用，不重复建档
- 单指令触发：核对摘要和入口
- 执行调度：确认条目范围 → 取得日志／来源结果 → 更新摘要与入口 → 核验；依赖失败不冒充成功

## lgx-vault

- 定义：界定当前库与灵感库的分工、编辑主体及日记用途。
- 库体现：DIFF 的两库差异简述；当前约定为规则库由 Agent 写、用户阅读，灵感库由用户写、Agent 阅读；灵感库日记由用户写，规则库日记即更改记录。分工不自动授予外部库访问权限。
- 原则：区分用途与操作权限，不因声明两库关系就读取另一库；实际分工内容由用户明确。
- 边界：不合并、同步或迁移两库，不猜测尚未定义的编辑主体与日记规则。
- 输出：已确认的分工声明、差异与待定项。
- 接口依赖：用户确认的两库声明。返回分工、编辑主体和日记用途，不读取另一库来猜测
- 单指令触发：核对已提供的分工声明
- 执行调度：澄清实际分工 → 评估 → 确认 → 仅更新指定说明

## lgx-change-log

- 定义：维护实质变更记录的规则及获准日志条目。
- 库体现：系统目录的每日变更记录与模板，DIFF 的日期入口及一句结果摘要。
- 吸收基线：复用现有系统说明与日记录机制，Daily Notes 与 Agent 共用一份记录；每日一篇、批次合并、新条目置顶、UTC+08:00，条目含结果、路径、会话、核验。DIFF 日期倒序、一日一条，不镜像日志；纯答疑及仅维护会话身份与必要引用不单独触发日志。位置作为输入，不固化原库路径。
- 原则：区分变更与答疑，记录结果、受影响范围与实际核验；详细记录和 DIFF 摘要职责分离。
- 边界：日志位置、格式与时间规则以目标输入为准，未指定时澄清；不编造核验或重复镜像摘要。
- 输出：实际日志条目、入口、核验依据与来源关联状态。
- 接口依赖：lgx-session-log、lgx-system（需要创建记录结构时）。提交获准条目和可核验来源，接收关联状态；目录创建与日志内容维护分开
- 单指令触发：检查指定日志
- 执行调度：明确记录请求／获准实质变更 → 确认位置、格式与时间规则 → 写条目并委托来源关联 → 核验，纯答疑不记

## lgx-session-log

- 定义：维护变更条目的会话来源规则和获准来源关联。
- 库体现：系统目录的最小会话身份卡及变更记录中的来源链接，DIFF 仅提供会话记录入口。
- 吸收基线：现有 session-records 的 link-changelog 归本模块；每会话一张身份卡，本库 UUID session_id 与可信宿主 source 分开，首次建卡前核验来源并查重，source 唯一匹配才复用。最小字段为 type、created、session_id、source，有可信链接时保留打开入口；不以标题、日期或临时目录推断身份。重复、缺字段或来源冲突停止关联，不覆盖；内容不变零写入，未知来源标待核验，不造占位卡，建卡并入原任务。
- 原则：来源必须有可核验证据，区分会话标识与标题；身份未知或冲突明确报告，不猜测归属。
- 边界：不默认记录完整聊天、敏感原文或执行会话恢复；回复切片目标职责交 lgx-catch，实际迁移未执行，现有预留接口仍不视为可用。存储位置由目标输入，必要目录由系统接口处理。
- 输出：来源证据、关联结果和未完成项，不将预留能力当成已实现。
- 接口依赖：可信宿主来源、lgx-system（需要创建记录结构时）；仅在获准切片请求中为 lgx-catch 提供身份关联。返回来源证据和关联状态，不因取得身份就采集会话正文。
- 单指令触发：核对指定来源关联
- 执行调度：核实来源与身份契约 → 仅关联获准条目 → 核验；未知、冲突或接口未定义时报告，不猜测

## lgx-readme

- 定义：维护 README.md 的概念声明、应用边界及根文件功能路标。
- 库体现：README 的常用概念、应用边界、使用简述与根文件入口；clear、rebuild、grammar、yaml 等功能的简述由所属技能提供。
- 原则：只保存本库必要概念、用途、边界及简短路标，详细规则由对应概念技能维护。
- 边界：根文件入口用别名与 Obsidian 格式链接，只作简短路标；内容导航仅链接 INDEX，不重复目录入口或详细策略。
- 输出：四个模板章节及有效链接，不在常用概念中混入结构别名清单。
- 接口依赖：lgx-job、lgx-statement、lgx-git、lgx-obsidian、lgx-grammar 及需简述的技能。只引用明确的功能与操作说明，内容导航只链接 INDEX。
- 单指令触发：检查说明一致性
- 执行调度：参考概念、用法与策略 → 确认范围 → 创建／修改四个章节 → 核验根文件路标，不复制内容导航

## lgx-statement

- 定义：归纳本库概念、定义及概念与个人技能的对应关系。
- 库体现：常用概念放 README，根文件与结构化目录别名放 INDEX；个人技能别名通过 lgx-skill 的独立别名映射提供，不混入 DIFF 纯名称分组。
- 原则：定义简洁、消除歧义，概念声明与技能可用状态分开；个人技能往往承载概念，但不是所有概念都必须生成技能。
- 边界：不重复维护个人技能名称清单，不凭概念名称自动创建或调用技能。
- 输出：分开的常用概念、个人技能别名、结构别名三类声明及对应目标，不复制技能名称登记。
- 接口依赖：lgx-skill 的名称／模块查询。取得已有技能映射，不重建名称清单，不将概念声明当作可调用证明
- 单指令触发：检查概念歧义与重复
- 执行调度：核对已有概念与技能映射 → 评估 → 确认 → 更新必要声明，不生成新技能

## lgx-git

## lgx-struct

- 定义：唯一维护目录骨架、层级、命名及分布式约束的存放与发现约定。
- 结构基线：目录围绕主要负责对象组织，实例名称与路径由规划传入；六分区由各自技能创建／维护，模板仅定义布局，不复制业务规则。点文件夹采用点号命名，实际列表与树视图归 lgx-tree；带隐藏属性但非点号的项不擅自改名。
- 归属与迁移：根文件职责归 lgx-job，结构别名由 lgx-statement 提供并在 INDEX 展示；现有命名差异先报告，重命名和内容迁移另获授权。
- 专属结构：收集区看板归 lgx-panel、摘抄归 lgx-sign，不重复收件箱正文；系统区承载自定义管理说明、元数据说明、记录与图源，分别交所属概念技能维护。身份卡、切片和日志通过链接关联，不镜像全文。
- 库体现：规划采用的目录骨架、INDEX 的结构展示及各目录的必要本地约束；布局归本模块，别名语义归 lgx-statement。
- 原则：结构性对象用英文，正文用中文；根文件大写，目录文件夹大写开头，目录内结构性文件小写，约束文件按下述层级特例。具体目录名称由确认的实例方案给定，不自动迁移旧名。
- 分布式约束：核心约束位于根目录，下级仅保留本地选择、例外和入口；一级目录用 INSTRUCTIONS、二级用 Instructions、更深层按需用小写。这是组织命名，扩展名和自动发现机制须明确并核验，不保证宿主按大小写自动加载。
- 模板：二级目录按实际需要组织介绍／本地约束、任务、看板、历史、计划、关键决策与列表入口；各对象互不干涉，结构性笔记用小写英文，历史版本与衍生正文按需拆入三级目录，不预建空分类。
- 边界：只维护布局与发现约定，约束正文归所属概念技能，根文件职责归 lgx-job；各分区由对应技能处理。
- 输出：结构规则、目录模板、实例差异及约束发现机制的验证状态。
- 接口依赖：lgx-job（涉及根文件职责时）。提供目录模板与约束布局，根文件职责以 job 为准，不接管各概念正文
- 单指令触发：检查结构约定
- 执行调度：评估命名、层级与影响 → 确认 → 更新获准规范／结构 → 核验发现机制；内容迁移另获授权
